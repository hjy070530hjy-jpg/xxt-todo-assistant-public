## 上游如何实现

MemSwapService 防止并发请求，读取清理前后系统可用物理内存，向独立提权进程提交操作，再显示净增加量。MemSwapWorks 通过 NtSetSystemInformation 操作工作集、文件缓存、已修改页面和待机列表，并提供注册表协调与物理页合并操作。其系统内存列表操作使用信息类别 80，其中命令 2 清空工作集，命令 4 清理待机列表；可用物理内存通过 GlobalMemoryStatusEx 读取。

## 本项目的实现

使用 Python ctypes 独立编写 Windows API 调用；没有引入 PCL 程序、C# 源文件、DLL、服务或驱动。

- 采用其中工作集清理和待机列表清理两项，不调用文件缓存强制收缩、脏页写回、注册表协调或物理页合并。
- 暂时启用现有令牌中的 SeProfileSingleProcessPrivilege，结束后恢复原状态，不永久改变系统权限配置。
- 普通权限运行时通过 Windows runas 启动本程序自身的无界面清理入口；用户自行处理系统 UAC。取消授权时显示取消结果，不冒充成功，也不让整个查询界面常驻管理员权限。
- 工作线程运行，单击不执行，双击图标执行；执行期间阻止重复触发。等待清理结果后才退出主程序。
- 成功量为 `max(0, 清理后可用物理内存 - 清理前可用物理内存)`，同时显示当前可用量。数字是采样时的系统净变化，受其他程序影响，不能当作仅由本工具独占释放的字节数，更不是永久性能提升。
- 两项操作独立记录结果；全部失败不显示成功，部分失败有明确提示。没有净增加时显示零及说明，不显示负的“释放量”。
- 新绘制的 assets/memory-clean.svg 是本项目的矢量图标，与百宝箱的图标按钮和悬停浮层共用样式。

## 验证与限制

Windows 11 x64 本机实际调用了两项清理，均返回成功；42项自动化测试覆盖计量、负差值、部分失败、权限不足、双击触发、防重复执行及原有功能。结果不是模拟值。手动 UAC 交互与其他 Windows 版本尚未完成独立实机验收。

NtSetSystemInformation 的这些内存操作不属于稳定公开的跨版本 Win32 接口。其他 Windows 版本、受管理设备或权限受限账户可能拒绝操作；此时保留错误状态。缓存重新载入可能造成短暂额外读盘，因此只提供手动触发，不定时反复清理。

微软参考：[GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)、[AdjustTokenPrivileges](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-adjusttokenprivileges)。
